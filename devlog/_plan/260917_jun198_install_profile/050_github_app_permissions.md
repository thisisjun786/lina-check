# 050 · GitHub App 권한 범위 도출 (wp4)

## 이 문서가 하는 일과 하지 않는 일

소스가 실제로 부르는 GitHub 엔드포인트에서 필요한 권한을 역산한다. App 을 만들지 않고
설치하지 않는다. 토큰을 발급하지 않는다. 여기 적힌 범위는 설치 운영자가 App 을 만들 때
참고하는 도출 결과이고, 이 저장소에 적용된 설정이 아니다.

## 도출 방법

원본 매니페스트나 워크플로에 적힌 권한 문자열을 베끼지 않는다. 그것은 원본 설치의 선택이고
이 저장소가 필요로 하는 범위와 다를 수 있다. 대신 호출부에서 올라간다.

1. 소스에서 GitHub REST·GraphQL 호출 지점을 전수 수집한다.
2. 엔드포인트와 HTTP 메서드를 뽑는다.
3. 각 엔드포인트가 GitHub 문서상 요구하는 권한과 수준(read / write)으로 매핑한다.
4. 호출부가 차단 명령·파킹 워크플로 뒤에 있는지, 현재 열린 표면인지 구분한다.
5. 현재 열린 표면에 필요한 최소 집합과, 운영 활성화 시 추가로 필요한 집합을 나눠 적는다.

4번을 나누는 이유가 있다. 이 저장소는 휴면 상태다. 지금 필요한 권한은 사실상 없고, 문서가
"이만큼 필요하다" 라고만 적으면 아직 필요하지 않은 권한을 지금 주게 된다. 단계를 나눠 적는다.

## 근거 원칙

각 행은 파일과 줄을 든다. "리뷰를 하려면 필요할 것" 같은 추정은 행이 되지 못한다.
호출이 없는 권한은 적지 않는다. 원본 워크플로가 요청하던 권한 중 이 저장소 소스에
대응 호출이 없는 것은 별도 표에 "원본이 요청했으나 근거 호출 없음" 으로 남긴다.

## 웹훅 이벤트

권한과 별개로 App 이 구독해야 하는 이벤트가 있다. `dashboard/worker.ts` 의 웹훅 처리 분기에서
같은 방식으로 도출한다. 이벤트는 권한이 아니지만 설치 시 함께 정해야 한다.

## 이 저장소에 적용된 것

없다. `config/lina-check-installation.json` 의 `github_app` 은 비어 있고
`dashboard/wrangler.toml` 의 `CLAWSWEEPER_APP_CLIENT_ID` 도 비어 있다.
`config/lina-check-scaffold.json` 의 `integrationsImplemented` 는 `false` 그대로다.
