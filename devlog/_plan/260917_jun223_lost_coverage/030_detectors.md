# 030 · 탐지기와 양성 대조

파생 테스트는 자식 프로세스를 띄우지 않는다. 이 문장을 증거 없이 적지 않기 위해 두 가지 탐지기를
두었고, 둘 다 자기 자신의 양성 대조를 먼저 통과한 다음에야 0을 주장한다. 둘 다
\`corepack pnpm run lina:contract-selftest\` 안에서 돈다.

## 왜 선언만으로는 부족했나

\`assertDerivedTestContract\` 는 선언된 파생 테스트 파일의 본문에서 금지 토큰을 찾는다.
그런데 \`test/helpers/command-intake-fixture.mjs\` 는 helper 안에서 \`fork()\` 한다. 파생 테스트가
그 helper 를 import 하면 본문은 깨끗하고 실행은 프로세스를 띄운다. 계약이 한 칸 모자랐다.

게다가 이 계약은 \`check:scaffold\` 에서만 불렸고 selftest 는 한 번도 부르지 않았다. 거부 경로가
실제로 거부하는지 아무도 확인하지 않는 상태였다는 뜻이다. 이번에 그 둘을 같이 고쳤다.

## 정적 탐지기 — 테스트 트리 import closure

\`derivedTestClosure\` 가 선언된 파일에서 시작해 상대 경로 import 를 따라간다. 테스트 트리
(\`test/\`) 안에 떨어지는 것만 따라가고, 나머지는 따라가지 않는다. 제품 모듈은 정당하게
프로세스 기동 표면을 갖고 있어서, 그것까지 금지하면 파생 테스트가 제품을 부를 수 없게 된다.
제품 쪽은 아래 런타임 탐지기가 본다.

양성 대조는 실제 바이트로 한다. 선언된 파일의 본문을 \`command-intake-fixture.mjs\` 를 import 하는
한 줄로 바꿔 계약에 먹인다. 그 한 줄에는 금지 토큰이 없다. 계약이 거부한다면 그것은 import 를
따라가 helper 안의 \`fork(\` 를 읽었다는 뜻이고, 거부 메시지가 helper 경로를 지목하는 것까지
단언한다. 본문에서 멈추는 스캔은 이 대조를 통과하지 못한다.

대조가 기대는 전제도 함께 지킨다. helper 가 언젠가 정리돼 \`fork(\` 를 잃으면 대조는 조용히
아무것도 증명하지 않게 되므로, helper 가 그 표면을 아직 갖고 있는지를 따로 단언한다.

## 런타임 탐지기 — 기동 0건 관측

선언된 파생 테스트 열한 개를 한 프로세스 안에서 import 해 실행하고, 그 프로세스에는
\`node:child_process\` 의 일곱 진입점(\`spawn\`·\`spawnSync\`·\`exec\`·\`execFile\`·\`execFileSync\`·
\`execSync\`·\`fork\`)을 감싼 preload 를 얹는다. 기록은 시도 시점에 남기므로 예외를 삼켜도 남고,
\`syncBuiltinESMExports()\` 로 ESM 바인딩까지 바꾸므로 named import 로 붙잡아 둔 참조도 따라온다.

양성 대조가 먼저다. 같은 preload 아래에서 무해한 sentinel(\`node -e ""\`)을 띄우고, 훅이 그것을
이름까지 기록하는지 확인한다. 그 다음에야 파생 테스트 쪽의 0건을 증거로 받아들인다.

실행도 같이 확인한다. 관측 실행이 exit 0 이고, 통과한 케이스 수가 기록된 하한(140) 이상이며,
실패가 0이어야 한다. 그러지 않으면 "아무것도 안 띄웠다" 가 "아무것도 안 돌았다" 와 구분되지 않는다.

## 이 탐지기가 보지 못하는 것

계측은 Node 안쪽에 건다. 계측이 얹히기 전에 함수 참조를 붙잡아 둔 코드, 감싼 함수를 다시 덮어쓰는
코드, 그리고 \`worker_threads\`·\`dgram\` 은 빠진다. 이건 적대적 코드에 대한 방어가 아니라 우리가
쓴 파생 테스트와 고정된 pin 에 대한 관측이다. 네트워크는 여기서 세지 않는다. 파생 테스트가 실제
요청을 하지 않는다는 것은 요청 경계를 대역 처리하고 시도 횟수를 0으로 단언하는 쪽
(\`lina-check-response-deadlines\`)에서 따로 본다.
